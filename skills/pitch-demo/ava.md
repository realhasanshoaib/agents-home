# Ava: a voice agent on their website

Every Ava demo runs on the shared engine at `https://agent.q9labs.ai`, built from `/Users/macmini/code/pitch-kit`. The engine already holds the guards, the rate limit, the call limit, the vendor keys and the widget, so a demo adds only a config and one script tag. Read `engine/README.md` ("Adopt it in five steps") and `widget/README.md` there before you start. Never copy widget or call code into a demo repo: fix it in pitch-kit, where every demo gets the fix.

- **The config.** Copy `pitch-kit/engine/demos/q9-sample.json` to the demo repo as `ava.config.json` and fill it in: the prospect's facts in the system prompt, the greeting, a voice per language, the origins of the demo's hostname, and the hash of a new access key. Push it with `ADMIN_KEY` from 1Password item "Pitch Kit Engine Admin Key": `pnpm --dir /Users/macmini/code/pitch-kit/engine demo:push <path>`. The engine never redeploys for a new demo. Save the access key in 1Password vault `dev` as "<Prospect> demo access key".
- **The widget.** Add `<script src="https://agent.q9labs.ai/v1/widget.js" data-demo="<id>" defer></script>` to every rebuilt page. Pick the template the request names: `panel` sits in the corner and opens as a bottom sheet on a phone, and `inline` fills a `<div data-ava-inline>` in a section such as the hero. A reskin changes only the `brand` fields and the labels in the config, as `widget/README.md` says. The link we send carries the key as `?k=<key>`, and the widget keeps it for the rest of the visit.
- **The agent.** Write the prompt for their customers from `research.md` and the brief. Keep the built-in tools `hangUp` and `openPage`, and add the tool the brief's hard moment needs, such as a booking lookup, so the demo shows it working instead of describing it. A `client` tool runs in the page through the `ava:tool` event, and an `http` tool calls the demo's own Worker.
- **The face.** Leave `avatar.enabled` off unless the request asks for a face, and check `GET /v1/health` before you turn it on, because a Tavus account with no credit shows only the fallback. Hasan rejected Simli, LemonSlice and Anam on quality, so Tavus is the only face.
- **When a vendor fails.** The widget shows `fallback` from the config instead of an error: its video when one exists, otherwise its image and text. Give every demo a fallback that shows the hard moment working, and test it on purpose with `/play/<id>` before you send the link.
- **The voice.** Pick a voice per language from samples. For an Arabic audience the voice must say prices in words and sound local.
- **Done** when a call and a chat started from the deployed site, with the key from the link, reach the brief's hard moment, and the pre-send check with `--demo <id>` passes.
