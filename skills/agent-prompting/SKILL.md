---
name: agent-prompting
description: Write or improve a system prompt. Use when drafting, reviewing, or debugging a persona or system prompt, when an agent sounds robotic, templated, or off-character, or when prompting a voice/phone agent (Ultravox, Vapi, LiveKit, ElevenLabs, Retell) for natural speech — covers both text/tool agents and voice agents.
---

A system prompt is a character brief for a literal actor: the model enacts whatever the words evoke, including the things you tell it not to do. Personality has to be written as behavior, not adjectives — "warm and friendly" gives the model nothing to play, whereas "asks the small follow-up instead of moving on, lets a silence sit, reacts before asking the next question" is actable. Show as much as you tell: a couple of concrete lines the agent might say, plus a couple of "avoid" lines that name the failure mode, teach faster than any amount of rule prose. State each rule once — the usual bloat is the same instruction restated across the persona, the behavior list, and the guardrails; the only repetition that earns its keep is an example demonstrating a rule you already gave.

Never name what you want the agent to avoid, because negation still primes: "don't steer them toward a CRM or an app" plants *CRM* and *app* in its head. State the goal positively with no forbidden nouns ("understand the problem in their own words; don't propose a solution"), and convert walls of prohibitions into the positive behavior they imply — keep hard "never" rules only for genuine limits like promises, claims, or leaking information, and give the exact line to say when pushed so it doesn't improvise a bad one. A workable shape: identity and mission in a few sentences, then personality as audible behaviors, then how it operates with examples, then what it's for (framed as judgment, not a script to march through), then the few guardrails, then its opening move. When improving an existing prompt, read it, name the specific weaknesses — robotic lines, primed-in nouns, echoed rules, adjective-only personality — then rewrite it as one coherent whole rather than patching, since patches accrete echoing rules.

Voice agents add one hard constraint: the output is spoken aloud through a TTS engine in real time, so write for the ear. Keep turns to a sentence or two, one question at a time (ask permission before unpacking a big one), and react before asking. Nothing that relies on the page survives speech — no lists, headings, emojis, markdown, or stage directions. Let grammar bend the way talk does: start with "So" or "And", always contractions, plain words. A real hesitation is a pause plus a restart, not a stray "um" — pair them ("yeah, um `<break time="300ms"/>` so, that depends"); a lone filler sounds fake. Keep emotion stable: at most one inline emotion tag per turn on a short phrase, never ping-ponging mid-sentence. Speak numbers as a person does — codes and phone numbers digit by digit, years naturally ("twenty twenty-six"), times as "10 AM", decimals as "point" then each digit. Treat inline markup as seasoning that most turns don't need, and note which dialect the voice uses (Cartesia Sonic, SSML, ElevenLabs tags) since they differ. Script the opening, but tell it to vary the wording rather than recite.
